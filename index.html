1「言葉」とは：命令セット 講義前半（別PDF）

CPU は日本語も C も分からない。分かるのは、あらかじめ決められた命令の一覧（命令セット）だけ。これが「コンピュータの言葉」。MIPS は命令セットの1種類で、特徴は全命令が 32bit 固定長であること。

人間が書く(アセンブリ)   addi $sp, $sp, -8
        ↓ アセンブラ
CPUが読む(機械語)        0010 0011 1011 1101 1111 1111 1111 1000  = 0x23BDFFF8

アセンブリと機械語は1対1で対応する。mnemonic（addi など）は機械語の op/funct に付けた人間用の名前に過ぎない。

よくある誤解「レジスタは命令を入れるところ？」→ いいえ。命令はメモリに置かれている。CPU は PC（次の命令のアドレス）が指すメモリから命令を取り出して実行する。レジスタは、命令が計算に使うデータの作業台。

2材料：レジスタとメモリ

レジスタメモリ
数32個（各32bit）何十億バイト
速さ非常に速い遅い
呼び方番号／名前（$t0）アドレス（1バイトごとに番号）
演算できる直接はできない

MIPS の演算命令が触れるのはレジスタだけ。メモリの値を計算に使うには、いったんレジスタへ運ぶ（lw）、結果はメモリへ書き戻す（sw）。これが後で出てくる「退避・復元」の正体。

1語 = 32bit = 4バイト。メモリのアドレスはバイト単位なので、隣の語は +4 番地。「アドレスに ×4」が頻繁に出てくるのはこのため。

3算術命令：宛先, 元1, 元2 p.80前後（前半PDF）

add  $t0, $s1, $s2     # $t0 = $s1 + $s2
sub  $t0, $s1, $s2     # $t0 = $s1 - $s2
addi $t0, $s1, 5       # $t0 = $s1 + 5   （第3項が定数）
mul  $v0, $a0, $v0     # $v0 = $a0 * $v0
  • 書き方は「宛先が先頭」。機械語では順番が違う（R形式は rs rt rd の順で、rd＝宛先が最後）。ここが入れ替わるのでミスしやすい。
  • $zero は常に 0。addi $v0,$zero,1 は「0+1」で定数 1 を $v0 に入れる。
  • 減算に subi は無い。addi に負の定数を使う（addi $sp,$sp,-8）。

例 f = (g+h) - (i+j) ※ g,h,i,j = $s1〜$s4, f = $s0

add $t0, $s1, $s2     # t0 = g+h
add $t1, $s3, $s4     # t1 = i+j
sub $s0, $t0, $t1     # f  = t0 - t1

4メモリの出し入れ：lw / sw とオフセット

lw  $t0, 8($s3)     # $t0 ← Mem[ $s3 + 8 ]   （メモリ → レジスタ, load word）
sw  $t0, 8($s3)     # Mem[ $s3 + 8 ] ← $t0   （レジスタ → メモリ, store word）

8($s3) の読み方：ベース＝レジスタ $s3 の中身（アドレス）、オフセット＝8。アクセス先は $s3 + 8 番地。

オフセットはレジスタ上の定数ではない。命令の機械語の中の imm（16bit）フィールドに直接埋め込まれた定数。レジスタの中身は変わりうるが、オフセットは命令に焼き込まれて不変。 だから sw $ra, 4($sp) は「$sp が指す場所の 4 バイト先」と読む。

手で触る：配列 A[i] の番地（A の先頭アドレスが $s3 = 0x4000, 要素は4バイト）

5比較と分岐：if を作る p.97-99

MIPS に「if (a < b) goto L」という1命令は無い。2命令に分ける：

slti $t0, $a0, 1        # $a0 < 1 なら $t0 = 1、そうでなければ 0
beq  $t0, $zero, L1     # $t0 == 0 なら L1 へ分岐
  • slt 系は結果を0/1としてレジスタに入れる（真=1、偽=0）。
  • beq/bne は「2つのレジスタが等しい／等しくない」だけ判定する。$zero と比べれば「0か否か」。
  • なぜ blt が無い？ ハードウェアで「大小比較」は「等しいか」より遅く、クロックを上げにくいから（p.98）。よく使う == と != だけ速くする設計の妥協。
fact で一番ひっくり返りやすい所：beq $t0,$zero,L1 は $t0==0 のとき L1 へ飛ぶ。
$t0 は「n<1 なら 1」だったので、$t0==0 ＝ n≧1（偽）。つまり n≧1 のとき L1（else側・再帰）へ飛び、n<1 のときは飛ばず下の「結果は1」に落ちる。C の if (n<1) と分岐の向きが逆に見えるのはこのため。
nslti → $t0beq $t0==0 ?行き先
01 (0<1 真)いいえ下へ落ちる → 結果 1（基底ケース）
30 (3<1 偽)はいL1 へ → 再帰

符号付き vs 符号なし（p.98-99）：slt は符号付き、sltu は符号なし。全bitが1の値は、符号付きでは -1、符号なしでは 4294967295。同じ32bitでも読み方で大小が変わる。

6PC とジャンプ：jal と jr p.117-121

PC（プログラムカウンタ）＝次に実行する命令のアドレス。命令は4バイトなので、通常は毎回 PC ← PC + 4。これを書き換える命令だけが「飛ぶ」：

命令PC がどうなるか
beq / bne成立時だけ PC+4 + オフセット×4（近くへ）
j LL へ（26bit のアドレス部 ×4 で遠くへ）
jal L$ra ← PC+8（戻り先を記録）してから L へ。
実機では jal の次の1命令（遅延スロット、通常 nop）も先に実行される設計なので、その次＝PC+8 に戻る（PC+4 と書く教科書の簡略説明もある）
jr $raPC ← $ra の中身（記録しておいた戻り先へ）
jal の link ＝「戻り先を結びつけて残す」。jal と jr $ra はワンセット：呼ぶとき jal が帰り道を $ra に置き、終わるとき jr が $ra の道を辿る。
分岐オフセットも ×4 される理由：命令は4バイト境界にしか無いので、下位2bitは常に00。省いた分、16bitで ±3万命令先まで届く（p.120）。

7手続き（関数）：呼ぶ側と呼ばれる側の約束 p.100-103 / スライド12-17

手続きを呼ぶ手順（p.100）：①引数を置く → ②制御を移す → ③必要なメモリを確保 → ④仕事 → ⑤結果を置く → ⑥元に戻る。誰がどこに置くかはレジスタ利用規約で決まっている：

レジスタ役割約束
$a0–$a3 (4–7)引数呼ぶ側が置く
$v0,$v1 (2,3)結果呼ばれた側が置く
$t0–$t9一時用呼ばれた側は勝手に壊してよい
$s0–$s7保存用使うなら呼ばれた側が保存→復元（返すとき元通りに）
$sp (29)スタックの先頭出るときは入る前の値に戻す
$ra (31)戻りアドレスjal が上書きする

踏み台：他の手続きを呼ばない例（leaf）C: f = g + h - i + j

leaf_example:               # g,h,i,j = $a0..$a3
  addi $sp, $sp, -4         # 1語ぶん枠を確保
  sw   $s0, 0($sp)          # $s0 を使うので退避（保存用だから）
  add  $t0, $a0, $a1        # g+h   ($t は壊してよいので保存不要)
  add  $t1, $a2, $a3        # i+j
  sub  $s0, $t0, $t1        # f = ...
  add  $v0, $s0, $zero      # 結果を $v0 へ
  lw   $s0, 0($sp)          # $s0 を元に戻す
  addi $sp, $sp, 4          # 枠を解放
  jr   $ra                  # 戻る
fact と同じ型：①枠を確保 → ②退避 → ③仕事 → ④復元 → ⑤枠を解放 → ⑥jr。leaf は他を呼ばないので $ra を退避する必要が無い（jal で上書きされないから）。次の段は、その必要が生まれる場面。

8スタック：自分用の机を借りる p.103-107 / スライド21-22

  • メモリの一角を後入れ先出し（LIFO）で使う領域。アドレスの大きい方から小さい方へ伸びる（下向き）。
  • $sp は「いま積まれている一番上（＝アドレスが一番小さい）」を指す。
  • MIPS に push/pop 命令は無い。自分で書く： 
    push 1語:  addi $sp,$sp,-4   →  sw $x,0($sp)
pop  1語:  lw   $x,0($sp)    →  addi $sp,$sp,4
  • 確保＝ $sp を減らす、解放＝ $sp を増やす。解放しても中身は消えない（上書きされるまで残る）。ただし「$sp より下」は使用済みとして扱うので、そこを読んではいけない。

fact は1回の呼び出しごとに 2語（$ra と $a0）の枠を取る。呼び出しごとに別の枠ができるから、再帰の各段が自分の $a0・$ra を別々に持てる。

10確認問題（答えは開いて確認）

    
Q1. lw $a0, 8($s3)、$s3 = 0x4000 のとき、どのアドレスの語を読む？0x4000 + 8 = 0x4008。オフセット 8 は命令の imm にある定数。

    
Q2. n = 0 のとき、beq $t0,$zero,L1 は飛ぶ？$t0 = (0<1) = 1。1 ≠ 0 なので飛ばない。下に落ちて「結果は 1」。

    
Q3. jal fact は $ra に何を入れる？PC+8（jal の次の遅延スロット nop を飛ばした先）。fact では lw $a0, 0($sp) の行。課題シートはこの設定。

    
Q4. 退避の sw $ra,4($sp) を忘れたらどうなる？fact が fact を呼んだ時点で $ra が内側の戻り先に上書きされ、外側の呼び出しが main に戻れず、同じ場所をぐるぐる回る（§9 の「退避しない」）。

    
Q5. jr $ra の機械語は R形式、jal は J形式。なぜ形式が違う？jr は「レジスタ（rs=31）の中身へ飛ぶ」のでレジスタ番号を持てばよく R形式。jal は「命令に書かれた固定の飛び先」なので26bit のアドレスを持つ J形式。

    
Q6. 基底ケースの addi $sp,$sp,8 は、n=0 で何をしている？入口で -8 して確保した2語の枠をそのまま解放している。中の $ra・$a0 は書き込んだが読まない（$ra は無傷なので復元不要）。

    
Q7. fact(3) の mul は何回実行され、いつ？fact(3), fact(2), fact(1) の3回（fact(0) は基底ケースで mul に到達しない）。いずれも戻ってきてから。順に 1×1=1 → 2×1=2 → 3×2=6。
